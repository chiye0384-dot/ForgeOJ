# 面试与设计取舍

这份说明帮助理解当前实现。能从代码和实测说明的事实，与个人已经掌握的内容，应分别表述。

## 用半分钟介绍项目

ForgeOJ 是一个面向 Java 学习和小班教学的在线判题平台。用户可以选题、保存草稿、自测、提交代码和复盘历史；教师可以布置作业，作者可以出题并审核发布。提交在 MySQL 中保存任务和 Outbox 事件，再经 RabbitMQ 交给独立 Worker，用 Docker 编译和运行冻结的代码与测试版本。

## 一次提交怎样避免丢失或重复处理？

提交、任务与事件同事务保存。MQ 确认后发布器标记事件；确认丢失允许重复投递。Worker 用数据库状态和租约条件领取，结果提交后再 ACK。旧 lease token 不能覆盖新 attempt 的结果。这里实现的是至少一次投递配合业务幂等，不是网络恰好投递一次。

## ES 没有 Maven SDK 依赖，为什么还说用了 ES？

当前使用 JDK HttpClient 调用 Elasticsearch REST API。ES 保存公开题搜索投影，返回候选后由 MySQL 复核当前版本和权限；ES 不可用时回退标题查询。客户端接入方式与是否使用搜索服务是两件事。

## 17.5 份/分钟是不是每份延迟 3.4 秒？

倒数约 3.43 秒表示平均完成间隔。三份在途时，单份提交到终态的 P50 约 9.9 秒，其中约 6.5 秒在排队，处理 P50 约 3.3 秒。顺序提交的终态 P95 约 4.11 秒。吞吐、处理时间、排队时间和页面轮询可见时间需要分别说明。

这些数字来自 Windows / Docker Desktop 上的 A+B、3 用例、单 Worker 短时测试；不是云端容量。测量条件与原始记录见[性能报告](../PERFORMANCE.md)。

## 大部分时间都用于建容器、启动 JVM 和编译吗？

原始 50 份正式记录中，处理时间平均约 3361ms；create、start、javac 和三次 java 调用的耗时合计平均约 1171ms，占约 34.8%。因此不能说“大部分时间都花在这几项上”。这些调用含 CLI 与采样开销，剩余部分还包含目录准备、资源检查、进程/文件清理和协调，不能直接归为单一瓶颈。

每份创建加启动的联合 P50 约 284ms；编译 P50 约 604ms，三次 java 合计 P50 约 276ms。各项分位数不能随意相加当作总耗时分位数。

## 为什么每次新建容器？

每个 attempt 有独立工作区、进程和资源限制，结束时清理。失效 attempt 的资源归属也能通过任务和 attempt 标识追踪。这样更容易检查文件、进程和资源计数是否跨提交残留。

复用容器或预热池可能减少创建和启动等待，但必须可靠地清空工作区与临时文件、终止子进程、处理 cgroup 资源计数、恢复权限，并防止旧 attempt 影响新任务。复用容器本身不会省去每份 javac 和每用例 JVM 启动；复用 JVM 又会引入跨程序状态与隔离问题。当前没有实现容器池，也没有无探针对照，不能承诺池化提升比例。

## 你和 AI 是怎么分工的？

可以如实说明：这个项目采用 AI 协作开发。我主要提出功能需求、使用体验反馈和改进优先级，AI 协助代码实现、排错、运行检查和整理文档。说明某个模块时，再具体区分自己实际阅读、解释、修改或验证过的内容与 AI 完成的内容。

AGENTS.md 与 .codex/skills/ 记录了协作规则和工作流程。保留这些文件能解释开发过程，但测试通过或文档完整并不自动证明个人已经掌握。不要把 AI 辅助产出描述为独立完成全部实现。
