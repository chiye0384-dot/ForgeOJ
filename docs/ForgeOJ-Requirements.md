## 2. 产品定位

ForgeOJ 是一个面向 Java 学习者、小型学习小组和班级教学的在线判题平台。

核心价值：

1. 安全隔离地执行用户 Java 代码。
2. 可靠地完成异步提交、判题、结果持久化和通知。
3. 支持公共刷题路线与班级作业。
4. 既提供判题结果，也提供可学习的官方题解和用户题解。
5. 让权限、审核、失败恢复和运维形成真实闭环。

目标部署规模：

- 固定 Linux 环境完成最终验收、故障演练和性能测试。
- 优先部署到阿里云 Linux ECS，供面试演示和少量真实学习者试用。
- 不承诺互联网级高可用、匿名代码执行或强敌对多租户安全。

## 3. 明确不做

V1.0 不包含：

- 多语言判题；
- 多文件工程和用户自定义 Maven 依赖；
- Special Judge、交互题、随机测试生成器和部分分；
- 竞赛、罚时、全站排行榜、签到或段位；
- 抄袭检测和在线监考；
- Spring Cloud、Gateway、注册中心、Kubernetes 和多机房；
- 动态按钮级 RBAC、MFA、企业 SSO 和复杂风控；
- 通用综合论坛。

## 4. 角色与权限

### 4.1 普通用户域

任何已激活普通账号都可以：

- 浏览公共题库和官方题单；
- 做题、运行自测、正式提交；
- 创建和管理本人私有题单；
- 创建个人题目草稿；
- 创建班级并成为该班 OWNER；
- 通过有效邀请码加入其他班级；
- 在 V1.1 发布本人 AC 对应的题解。

班级角色只在对应班级内生效：

| 角色 | 主要职责 |
|---|---|
| OWNER | 管理班级、成员、助教、邀请码、私有题、作业和班级归档；查看本班作业提交 |
| ASSISTANT | 协助维护班级私有题、作业和学习记录；不能转让或归档班级，不能任免助教 |
| MEMBER | 做题、完成作业、查看个人记录和参与允许的讨论 |

同一用户可以在不同班级拥有不同角色。OWNER 的日常教学权限包含 ASSISTANT，ASSISTANT 包含 MEMBER。

### 4.2 独立管理域

管理员账号不开放普通注册，不能做题、加入班级或发布普通题解。管理员使用独立登录入口。

| 后台角色 | 主要职责 |
|---|---|
| CONTENT_REVIEWER | 审核公共题目；处理题目反馈、版权和社区举报 |
| OPS_ADMIN | 处理判题异常、重试、死信和运行诊断 |
| SUPER_ADMIN | 拥有全部后台权限；创建、停用管理员并分配角色 |

首个 SUPER_ADMIN 必须通过一次性初始化命令创建，不允许在代码中保留默认密码。

## 5. 普通账号与认证

### 5.1 注册与找回

- 使用唯一用户名、唯一邮箱和密码注册。
- 邮箱验证后激活账号。
- 支持用户名或邮箱登录。
- 昵称仅用于展示，可以重复。
- 支持通过已验证邮箱找回密码。
- 开发环境使用本地邮件模拟器；生产环境配置 SMTP。

### 5.2 会话

- 使用短期 JWT 与独立登录会话。
- 每次登录生成独立会话 ID。
- MySQL 保存权威会话状态和刷新令牌摘要，Redis 缓存会话状态。
- 当前退出只关闭当前会话。
- 全部退出、改密、重置密码或账号封禁必须使全部旧会话失效。
- Redis 故障时回退到 MySQL 校验，不允许跳过校验直接放行。

### 5.3 安全基线

- 使用 BCrypt 保存密码摘要。
- 验证码和重置令牌限时、单次使用且不明文保存。
- 登录、验证码发送和密码重置必须限流。
- 登录和找回接口使用模糊提示，避免泄露账号是否存在。
- 安全日志不得记录密码、完整 Token 或验证码。

## 6. 题库与题单

### 6.1 公共题库

- 支持题目列表、难度和标签筛选、关键词搜索。
- 公共题必须经过 CONTENT_REVIEWER 的发布前审核。
- 题目至少包含题面、输入输出说明、公开样例、隐藏测试、资源限制、私有参考程序和官方题解。
- 官方公共题单由平台维护，支持类似 Hot 100 的完成进度。
- 普通用户可以创建个人私有题单；V1.0 与 V1.1 均不公开。
- 公开个人题单仅作为 V2.0 候选；即使以后实现也默认私有，必须由用户主动发布，并同时建设收藏/复制、举报、下架和注销后的归属规则。
- V1.0 不提供竞争排行榜。

### 6.2 个人题单

- V1.0 与 V1.1 的个人题单默认且只能本人可见，不提供公开入口。
- 支持创建、改名、删除题单，以及添加、移除和调整题目顺序。
- 只允许收录当前用户可浏览的公共题；V1.0 不收录班级私有题，避免题单成为越权入口。
- 进度只根据本人对当前题目判题版本的真实 AC 记录计算。
- 所有读取、修改和删除接口必须在后端校验 owner_id，不能只依赖前端隐藏，也不能通过题单 ID 枚举他人内容。
- 题目归档或对用户不可用时，题单只显示不可用占位，不返回受限详情，也不允许从题单发起新提交。
- V2.0 若实现公开能力，必须支持主动取消公开并恢复私有，且公开题单不得暴露任何非公开题目。

### 6.3 题目归属

- 未发布个人草稿归创建者。
- 发布为班级私有题后归班级，保留 created_by 供审计；助教退出不会删除题目。
- 班级私有题申请公开时复制为独立公共候选题，原班级的提交、作业和讨论不复制。
- 公共题通过审核后由平台控制发布状态，同时展示原作者和来源。

### 6.4 来源与许可

- 创建者必须声明“原创”或“基于允许使用的来源改编”。
- 改编题必须填写来源链接、许可证或授权说明。
- 禁止直接搬运付费或私有题库的题面、测试数据、官方题解和代码。
- 无明确许可的材料只能参考思想，不得复制内容。

### 6.5 审核与版本

- 提交公共审核时生成不可变审核版本。
- 审核期间修改必须先撤回。
- 审核员只能批准或驳回并填写原因，不能替作者修改内容。
- 已公开题目的非判题文案修改需要重新审核后整体替换。
- 输入输出规则、测试数据、比较规则或资源限制发生变化时，创建新题或新判题版本，不覆盖旧依据。

### 6.6 删除、归档与纠错

- 无发布、无引用、无提交的草稿可以物理删除。
- 产生业务记录后只能归档：停止搜索、选题和新提交，历史记录只读保留。
- 发现严重测试错误时，暂停旧题并标记“判题数据存在问题”。
- 创建关联的修正版新题；旧结果保留并标明来自已作废版本，不能证明修正版已经完成。
- 作业中的错误题标记无效，不再计为未完成；如需重做，教师另发布补充作业。

## 7. 测试数据、参考程序与官方题解

### 7.1 测试数据

- 支持网页逐条录入。
- 支持 ZIP 批量导入 001.in/001.out 等成对 UTF-8 文件。
- 限制文件数量、单文件大小和总大小。
- V1.0 不执行用户上传的测试生成脚本。
- 正确输出可以手工填写，也可以由私有参考程序批量生成并预览确认。

隐藏测试保存在 MySQL 独立受限表中，压缩保存输入、输出、顺序、大小和校验值。普通题目查询不得读取这些字段。

### 7.2 私有参考程序

- 所有正式公共题和班级私有题必须提供 Java 21 参考程序。
- 发布或送审前，参考程序必须在正式沙箱中通过全部测试。
- 个人草稿由创建者维护；班级题由 OWNER/ASSISTANT 维护。
- CONTENT_REVIEWER 可查看送审版本并重新运行，但不能修改。
- OPS_ADMIN 默认只看验证状态和脱敏错误。
- 普通做题者永远不能查看私有参考程序。

### 7.3 官方题解

官方题解与私有参考程序是两个独立对象。

- 所有正式公共题和班级私有题至少有一份官方题解。
- 官方题解必须包含核心思路和一份经过正式沙箱验证的代码。
- 标题由系统生成；时间、空间复杂度和严格证明选填。
- 每个当前 judge_version 只要求一份官方题解。
- 题解代码绑定对应 judge_version；代码修改或判题版本变化后必须重新验证。
- 私有参考程序不会因为官方题解开放而自动公开。

公共题：

- 用户 AC 后自动解锁官方题解。
- 未 AC 用户可以主动确认“可能影响独立思考”后提前查看。
- 提前查看只记录在个人学习记录中，不公开、不惩罚，也不禁止继续提交。

班级题：

- 每份作业分别选择 IMMEDIATE、AFTER_AC 或 AFTER_DEADLINE。
- 作业开始后不得修改该策略。
- 不属于作业的自由练习使用题目自身默认策略。

## 8. Java 作答与判题

### 8.1 源码范围

- 运行环境为 JDK 21。
- 用户提交单个完整 Main.java，公开类名必须为 Main，不允许 package。
- 只能使用 JDK 21 标准库。
- V1.0 不支持多文件和自定义 Maven 依赖。

### 8.2 运行与提交

- “运行”使用用户自定义输入，只用于调试，不产生 AC，可短期保存后清理。
- “提交”创建永久、不可变的正式记录。
- 两者都复制点击当时的代码快照，不引用后续变化的草稿。
- 服务端按“用户 + 题目 + 语言”保存一份自动草稿。
- 草稿带版本号，多页面冲突时必须提示，不允许静默覆盖。

### 8.3 异步链路

~~~text
用户提交
  -> API 在同一事务保存 submission 与 Outbox
  -> Outbox 发布 RabbitMQ
  -> Judge Worker 幂等消费
  -> 一次性 Docker 沙箱编译和运行
  -> 结果幂等写回 MySQL
  -> WebSocket 通知，查询接口兜底
~~~

要求：

- API 服务不能直接操作 Docker。
- RabbitMQ 消息只传任务 ID、提交 ID、任务类型和版本，不传隐藏测试。
- Worker 保存终态后才手动 ACK。
- 平台临时故障有限退避重试；用户代码错误不重试。
- 超过重试上限进入死信队列，由 OPS_ADMIN 处理。
- 同一次用户提交的每次执行写入 judge_task_attempt，不创建新 submission。
- 请求 ID 用于区分网络重发与用户主动再次提交。
- 每位用户最多一个运行中任务、三个排队任务。
- QUEUED 任务可取消；RUNNING 任务 V1.0 不支持用户强制取消。

### 8.4 状态与结果

处理状态与用户代码结果必须分开：

- 处理状态：QUEUED、RUNNING、RETRYING、FINISHED、CANCELLED、SYSTEM_ERROR。
- 判题结果：AC、WA、CE、RE、TLE、MLE、OLE、SECURITY_VIOLATION。

数据库是最终事实来源。WebSocket 只发送提交 ID、状态和单调递增版本；断线、超时或乱序时查询接口恢复。

### 8.5 编译与测试执行

- 每次正式提交创建一个全新容器。
- 源码只编译一次。
- 每个测试用例启动独立 JVM 进程并清理临时目录。
- 测试按固定顺序执行，遇到第一个非 AC 立即停止。
- 编译失败直接返回 CE。
- 安全违规、总资源预算耗尽或平台异常立即终止。
- 平台异常不得伪装成用户 RE。

输出比较：

- 规范化 Windows/Linux 换行；
- 忽略行末多余空白和文件末尾空行；
- 其他内容保持严格一致。

隐藏测试不得向普通用户返回输入、预期输出、失败编号、通过数量或逐例资源数据。编译错误和公开样例可以显示安全的详细信息。

### 8.6 沙箱安全

容器必须：

- 非 root；
- 禁止联网；
- 根文件系统只读；
- 使用受限临时目录；
- 删除多余 Linux capabilities；
- 启用 no-new-privileges；
- 限制 CPU、内存、进程数、输出量、单用例时间和整次提交预算；
- 不挂载数据库、Redis、MQ 凭证或整套隐藏测试；
- 任何终态都清理容器与临时文件。

普通 Docker 不被视为可以承载任意互联网恶意代码的绝对安全边界。

### 8.7 可复现性

每次正式提交保存：

- 源码及哈希；
- 语言；
- judge_version；
- 资源限制和比较规则版本；
- 测试数据校验值；
- 实际 Docker 镜像 tag 或 digest。

镜像升级只影响新提交，不自动重判历史记录。

## 9. 班级与作业

### 9.1 班级

- 任何普通用户都可以创建班级并成为 OWNER。
- 用户使用有效邀请码直接加入。
- OWNER 可以关闭或重新生成邀请码；现有成员不受影响。
- 主动退出记录为 LEFT，可凭当前邀请码恢复原成员记录。
- 被移出记录为 REMOVED，只能由 OWNER 恢复。
- 离开后立即失去私有内容访问权，历史作业和提交保留。

OWNER 转让：

- 只能转让给当前有效成员。
- 对方接受前原 OWNER 继续负责。
- 接受后新用户成为 OWNER，原 OWNER 默认降为 ASSISTANT。
- 运行中的班级必须先转让或归档，OWNER 才能退出。

班级删除与归档：

- 无其他成员、题目、作业和提交的空班级可以物理删除。
- 有业务数据后只能归档。
- 归档后停止加入、发布、班级提交和新增讨论；历史只读。
- 未开始作业停止启动，活动作业提前结束并记录原因。
- 恢复班级时不自动恢复旧作业；OWNER 可以复制后重新设置时间。

### 9.2 作业

- 作业可以引用公共题和本班私有题。
- 支持草稿、立即发布和定时开始。
- 开始时生成参与成员快照；后来加入者默认不承担旧作业，可由 OWNER/ASSISTANT 手动加入。
- 不限制尝试次数；整题第一次 AC 即完成。
- 只记录未开始、尝试中、按时 AC、迟交 AC、PRECOMPLETED 等状态，不做百分制和部分分。
- 作业可选择已有 AC 是否算完成。
- 命中已有 AC 时记录 PRECOMPLETED 并关联真实历史提交，不创建假提交，作业内尝试次数为 0。
- 创建者选择允许迟交或硬截止，默认允许迟交并标记。

开始前可以自由修改。开始后：

- 可以修正文案；
- 可以延长但不能缩短截止时间；
- 延期后按新截止时间重新计算迟交，只允许迟交升级为按时；
- 题目列表、已有 AC 规则、迟交规则和题解开放策略锁定；
- 实质变化必须取消旧作业并创建新作业；
- 已开始作业只能带原因取消，不能删除历史。

### 9.3 教师可见范围

OWNER/ASSISTANT 可以查看：

- 本班作业成员完成状态；
- 尝试次数和首次 AC 时间；
- 本班作业相关的提交记录和代码。

不能因为用户加入班级，就查看其在其他题目的私人练习。

## 10. 用户题解与社区

### 10.1 V1.1 用户题解

- 只能选择本人对当前题目的 AC 提交。
- 后端必须验证提交属于当前用户、对应当前题目和当前 AC 状态。
- AC 代码只读，标题、思路和复杂度可编辑。
- 想修改代码必须重新提交并 AC，再选择新的提交。
- 同一用户对同一题最多发布三篇题解。
- 标题最终必填；为空时使用《题目名称》题解模板，不调用 AI。
- 关联题目、语言和 AC 代码由系统结构化填充。
- 解题思路、时间复杂度和空间复杂度选填。
- 支持点赞、收藏和三层评论。

三层评论含义：

1. 问题或观点；
2. 回答；
3. 感谢或一次追问。

更深讨论另开根评论。

### 10.2 版本边界

- V1.0：官方题解，不包含普通用户题解社区。
- V1.1：用户题解、点赞、收藏、三层评论、题目绑定讨论。
- V2.0：增加可不关联题目的简单学习论坛，复用同一审核机制。
- 不做关注、私信、推荐流和复杂社交关系。

## 11. 内容治理

### 11.1 预审与事后审核

- 公共题必须发布前审核。
- V1.1 用户题解、讨论和评论直接发布，违规后通过举报处理。
- 举报数量只影响优先级，不能自动定罪或自动永久删除。

### 11.2 反馈与举报

- 题目反馈：题意歧义、样例错误、测试错误、资源限制不合理。
- 违规举报：版权、抄袭、泄露隐藏测试、辱骂、广告、作弊信息。
- 同一用户对同一内容只保留一条有效举报。
- 多个举报合并为一个审核案件。

### 11.3 软删除

- 题解或根讨论撤回后不再公开，但正式提交仍私有保留。
- 无回复评论可以隐藏；有回复评论显示“该评论已删除”，保留结构。
- 管理员下架必须填写原因，允许纠正后恢复。
- 所有敏感查看和处置进入审计日志。

CONTENT_REVIEWER 只能查看当前案件需要的最小上下文，默认不能浏览无关草稿、隐藏测试、参考程序或源码。

## 12. 管理后台

V1.0 必须形成以下闭环：

1. 独立管理员登录和后端角色校验。
2. 公共题待审核、批准、驳回和重新提交。
3. 失败/死信判题任务查询和幂等重试。
4. SUPER_ADMIN 创建、停用管理员并分配角色。
5. 管理员操作审计。
6. 权限矩阵集成测试。

不得仅通过隐藏前端按钮实现权限。普通用户访问后台 API 必须得到 403。

## 13. Redis 与 Elasticsearch

### 13.1 Redis

Redis 用于：

- 公共题目详情和官方题单缓存；
- 登录会话和 Token 失效状态缓存；
- 登录、提交和评论限流；
- 连续点击的短期幂等拦截。

MySQL 始终是用户、题目、作业、提交和判题结果的最终事实来源。

缓存策略：

- Cache-Aside；
- 修改 MySQL 时同事务写缓存失效 Outbox；
- 事务后可靠删除缓存；
- 空值短 TTL、防穿透；
- TTL 随机抖动、防雪崩；
- 热点缓存单请求重建、防击穿。

Redis 故障时：

- 公共缓存回退 MySQL；
- 会话回退 MySQL 权威记录；
- 限流回退单实例保守策略，并结合数据库排队数量；
- 不允许跳过安全检查。

### 13.2 Elasticsearch

- 只索引公共题目的标题、题面纯文本、难度和标签。
- 支持全文检索、难度/标签筛选和关键词高亮。
- 不索引班级私有题、隐藏测试、用户源码、题解和论坛。
- MySQL 是唯一事实来源。
- 发布、修改、下架通过 Outbox 同步。
- 索引消费者使用“题目 ID + 数据版本”幂等更新。
- 失败有限重试，最终进入死信队列。
- 提供从 MySQL 全量重建索引的管理操作。
- ES 仅返回候选 ID 和排序；API 批量查询 MySQL 复核当前公开状态。

ES 故障时，熔断并回退到 MySQL 标题关键词及精确标签/难度筛选；暂时失去正文检索、相关度排序和高亮，并显示降级状态。

## 14. 非功能要求

### 14.1 一致性与可靠性

- 数据库和 RabbitMQ 使用事务 Outbox，不使用分布式事务。
- 所有消费者按至少一次投递设计，必须幂等。
- Redis 和 ES 不得成为权限或业务事实的唯一来源。
- 平台失败与用户代码错误严格区分。

### 14.2 可观测性

- 结构化日志关联 requestId、submissionId 和 judgeTaskId。
- 提供健康检查和就绪检查。
- 采集请求延迟、队列深度、排队时间、判题耗时、结果分布、重试、死信、缓存命中、降级和容器清理失败。
- 使用最小 Prometheus/Grafana 面板。
- 不在 V1.0 建设完整 ELK 和分布式追踪。

### 14.3 测试

- 单元测试覆盖状态机、权限和关键规则。
- 集成测试覆盖 MySQL、Redis、RabbitMQ、ES、Outbox 和幂等。
- 权限矩阵测试覆盖用户、班级角色和后台角色。
- 端到端覆盖注册到 AC、班级作业、出题审核和异常任务重试。
- 沙箱测试覆盖无限循环、内存耗尽、进程爆炸、输出超限、联网、写文件、提权尝试、异常退出和清理。
- 不追求没有意义的 100% 行覆盖率。

### 14.4 部署、配置与备份

- 日常开发可使用 Windows、Docker Desktop 或 WSL2。
- 最终验收和性能数据来自固定 Linux 环境。
- 单机 Docker Compose 部署 Nginx、API、Judge Worker、MySQL、Redis、RabbitMQ、ES 和监控。
- 只有 HTTP/HTTPS 对外；基础设施只在内部网络。
- 真实密钥不得进入仓库、镜像、日志或错误响应。
- Flyway 管理数据库迁移。
- MySQL 每日加密备份并复制到服务器外；至少保留 7 份日备份和 4 份周备份。
- 正式验收前必须完成一次恢复演练和一次应用回滚演练。

### 14.5 性能真实性

- 不预写 QPS。
- Web API、缓存/搜索、提交接收、判题吞吐和 WebSocket 延迟分别测试。
- 所有数据记录固定环境、数据集、预热、并发、时长、错误率、资源占用和 Git commit。
- 只有可复现的优化前后对比才能写“提升百分比”。
