## 2. 产品定位

ForgeOJ 是一个面向 Java 学习者、小型学习小组和班级教学的在线判题平台。

核心价值：

1. 安全隔离地执行用户 Java 代码。
2. 可靠地完成异步提交、判题、结果持久化和通知。
3. 支持公共刷题路线与班级作业。
4. 既提供判题结果，也提供可学习的官方题解和用户题解。
5. 让权限、审核、失败恢复和运维形成真实闭环。

目标部署规模：

- 固定 Linux 环境完成最终验收、故障演练和性能测试。
- 优先部署到阿里云 Linux ECS，供面试演示和少量真实学习者试用。
- 不承诺互联网级高可用、匿名代码执行或强敌对多租户安全。

## 3. 明确不做

V1.0 不包含：

- 多语言判题；
- 多文件工程和用户自定义 Maven 依赖；
- Special Judge、交互题、随机测试生成器和部分分；
- 竞赛、罚时、全站排行榜、签到或段位；
- 抄袭检测和在线监考；
- Spring Cloud、Gateway、注册中心、Kubernetes 和多机房；
- 动态按钮级 RBAC、MFA、企业 SSO 和复杂风控；
- 通用综合论坛。

## 4. 角色与权限

### 4.1 普通用户域

任何已激活普通账号都可以：

- 浏览公共题库和官方题单；
- 做题、运行自测、正式提交；
- 创建和管理本人私有题单；
- 创建个人题目草稿；
- 创建班级并成为该班 OWNER；
- 通过有效邀请码加入其他班级；
- 在 V1.1 发布本人 AC 对应的题解。

班级角色只在对应班级内生效：

| 角色 | 主要职责 |
|---|---|
| OWNER | 管理班级、成员、助教、邀请码、私有题、作业和班级归档；查看本班作业提交 |
| ASSISTANT | 协助维护班级私有题、作业和学习记录；不能转让或归档班级，不能任免助教 |
| MEMBER | 做题、完成作业、查看个人记录和参与允许的讨论 |

同一用户可以在不同班级拥有不同角色。OWNER 的日常教学权限包含 ASSISTANT，ASSISTANT 包含 MEMBER。

### 4.2 独立管理域

管理员账号不开放普通注册，不能做题、加入班级或发布普通题解。管理员使用独立登录入口。

| 后台角色 | 主要职责 |
|---|---|
| CONTENT_REVIEWER | 审核公共题目；处理题目反馈、版权和社区举报 |
| OPS_ADMIN | 处理判题异常、重试、死信和运行诊断 |
| SUPER_ADMIN | 拥有全部后台权限；创建、停用管理员并分配角色 |

首个 SUPER_ADMIN 必须通过一次性初始化命令创建，不允许在代码中保留默认密码。

2026-10-08补充确认（D-043）：一个管理账号只分配上述一种角色；同一人兼任内容审核和运维时分配两个账号，SUPER_ADMIN仍拥有全部后台能力。管理员新建、一次性bootstrap或密码重置后必须首次改密；SUPER_ADMIN可重置其他管理员，全部SUPER无法登录时由操作者通过服务器本机显式恢复指定既有SUPER并保留持久审计。不开放管理员普通注册或普通用户邮件找回入口。具体会话、并发保护、初始化/恢复与验收合约见 [首单元设计](M4-ADMIN-IDENTITY-DESIGN.md)，本身份单元已实现并[验收](M4-ADMIN-IDENTITY-VALIDATION.md)，不代表其余后台业务权限已交付。

## 5. 普通账号与认证

### 5.1 注册与找回

- 使用唯一用户名、唯一邮箱和密码注册。
- 邮箱验证后激活账号。
- 支持用户名或邮箱登录。
- 昵称仅用于展示，可以重复。
- 支持通过已验证邮箱找回密码。
- 开发环境使用本地邮件模拟器；生产环境配置 SMTP。

### 5.2 会话

- 使用短期 JWT 与独立登录会话。
- 每次登录生成独立会话 ID。
- MySQL 保存权威会话状态和刷新令牌摘要，Redis 缓存会话状态。
- 当前退出只关闭当前会话。
- 全部退出、改密、重置密码或账号封禁必须使全部旧会话失效。
- Redis 故障时回退到 MySQL 校验，不允许跳过校验直接放行。

### 5.3 安全基线

- 使用 BCrypt 保存密码摘要。
- 验证码和重置令牌限时、单次使用且不明文保存。
- 登录、验证码发送和密码重置必须限流。
- 登录和找回接口使用模糊提示，避免泄露账号是否存在。
- 安全日志不得记录密码、完整 Token 或验证码。

### 5.4 M2 账号实施合约

2026-10-02 用户已确认 D-041 的全部推荐方案，详细参数和接口见 [普通账号设计](M2-ACCOUNTS-DESIGN.md)。首个实施单元包括注册、邮箱激活、短 JWT 与独立 MySQL 会话、refresh 轮换/重用撤销、当前/全部退出、改密、邮箱找回以及旧账号补邮箱；现为 `VERIFIED`。固定 Linux 后端 211 / 前端 13 项、真实注册到 AC、独立权限/日志/队列审计和精确清理见 [账号验收记录](M2-ACCOUNTS-VALIDATION.md)。完整 M2 仍为 `IN_PROGRESS`，不表示全部 M2 门禁或生产 SMTP 通过。

- 新账号为 `PENDING_VERIFICATION`，激活后为 `ACTIVE`，停用为 `DISABLED`；用户、quota lock 与激活令牌摘要同事务建立。
- 新用户名为 3–32 个 ASCII 字母、数字或下划线，唯一性不区分大小写；邮箱支持常见 ASCII 地址，trim/lowercase，不合并供应商别名。昵称可以重复；新密码至少 12 字符、最多 72 UTF-8 字节，不 trim。
- 访问 JWT 最长 5 分钟，每次登录的 MySQL 会话绝对期限为 7 天；受保护 HTTP 请求复核账号和会话，敏感写在事务内再次检查。Refresh 为随机 256 bit，数据库只存摘要，轮换后的旧令牌重用撤销该会话。
- 浏览器认证使用 host-only、HttpOnly、SameSite=Strict Cookie，生产使用 Secure；写请求同时校验精确同源 Origin 和 CSRF。Token 不进入 JSON、localStorage 或 WebSocket URL；登录和身份变更轮换 CSRF，refresh 保留 CSRF。
- 既有 ID、密码摘要、状态、quota 与提交历史保留。旧 `ACTIVE` 用户仍可用户名登录；没有伪造邮箱或验证时间，必须以当前密码申请并验证邮箱后才能找回密码。旧进程会话升级后重新登录。
- 本地开发邮件模拟器仅供 `dev`/`test`，绑定 loopback，独立端口且内存有界；默认邮件模式为 `disabled`。本轮不连接真实 SMTP，生产邮件配置/投递与可靠重试仍须在上线前完成。Redis 会话缓存和分布式限流留在 M4，当前直接查询 MySQL，不跳过安全校验。

- 审核员只能批准或驳回并填写原因，不能替作者修改内容。
- 已公开题目的非判题文案修改需要重新审核后整体替换。
- 输入输出规则、测试数据、比较规则或资源限制发生变化时，创建新题或新判题版本，不覆盖旧依据。

### 6.6 删除、归档与纠错

- 无发布、无引用、无提交的草稿可以物理删除。
- 产生业务记录后只能归档：停止搜索、选题和新提交，历史记录只读保留。
- 发现严重测试错误时，暂停旧题并标记“判题数据存在问题”。
- 创建关联的修正版新题；旧结果保留并标明来自已作废版本，不能证明修正版已经完成。
- 作业中的错误题标记无效，不再计为未完成；如需重做，教师另发布补充作业。

## 8. Java 作答与判题

### 8.1 源码范围

- 运行环境为 JDK 21。
- 用户提交单个完整 Main.java，公开类名必须为 Main，不允许 package。
- 只能使用 JDK 21 标准库。
- V1.0 不支持多文件和自定义 Maven 依赖。

### 8.2 运行与提交

- “运行”使用用户自定义输入，只用于调试，不产生 AC，可短期保存后清理。
- 已验收策略为终态后24小时隐藏并物理清理自测代码、输入和输出；最少不可变元数据、幂等生命周期与关闭 attempt 保留，作为重放隔离和沙箱清理的权威依据，见 L-038。
- “提交”创建永久、不可变的正式记录。
- 两者都复制点击当时的代码快照，不引用后续变化的草稿。
- 服务端按“用户 + 题目 + 语言”保存一份自动草稿。
- 草稿带版本号，多页面冲突时必须提示，不允许静默覆盖。

### 8.3 异步链路

~~~text
用户提交
  -> API 在同一事务保存 submission 与 Outbox
  -> Outbox 发布 RabbitMQ
  -> Judge Worker 幂等消费
  -> 一次性 Docker 沙箱编译和运行
  -> 结果幂等写回 MySQL
  -> WebSocket 通知，查询接口兜底
~~~

要求：

- API 服务不能直接操作 Docker。
- RabbitMQ 消息只传任务 ID、提交 ID、任务类型和版本，不传隐藏测试。
- Worker 保存终态后才手动 ACK。
- 平台临时故障有限退避重试；用户代码错误不重试。
- 超过重试上限进入死信队列，由 OPS_ADMIN 处理。
- 同一次用户提交的每次执行写入 judge_task_attempt，不创建新 submission。
- 请求 ID 用于区分网络重发与用户主动再次提交。
- 每位用户最多一个运行中任务、三个排队任务。
- `QUEUED/RETRYING` 合计占用三个排队名额；运行中始终允许另有三个排队任务，不为未来重试预占名额。排队已满时，平台失败的任务在内部 `WAITING_RETRY` 状态保留原运行槽位等待有限重试，对外仍为 `RUNNING`；不额外创建排队任务，亦不允许后续任务抢占该槽位。
- QUEUED 任务可取消；RUNNING 任务 V1.0 不支持用户强制取消。
- 取消使用 `POST /api/v1/submissions/{submissionId}/cancel`，仅所有者且须通过会话/CSRF 校验。已取消的重复请求幂等成功；其他非排队状态返回 409；他人、不存在及格式错误的提交统一 404。取消保留历史记录，不删除提交或尝试记录。

### 8.4 状态与结果

处理状态与用户代码结果必须分开：

- 处理状态：QUEUED、RUNNING、RETRYING、FINISHED、CANCELLED、SYSTEM_ERROR。
- 判题结果：AC、WA、CE、RE、TLE、MLE、OLE、SECURITY_VIOLATION。

当前 M1 资源结果的实现定义见 D-040：通过可信内核 cgroup v2 的逐例增量识别内存分配失败（MLE）与进程数上限违规（SECURITY_VIOLATION）。被程序自行打印/抛出的 OOM 文本、退出码或无法审计的拒绝操作不单独作为结果依据；缺少可信证据时保留原运行错误/输出判定或平台失败。纯 JVM 堆/metaspace OOM 的通用可信识别仍为已知差距，见 L-032。

数据库是最终事实来源。WebSocket 只发送提交 ID、状态和单调递增版本；断线、超时或乱序时查询接口恢复。

通知合约使用 `/api/v1/submissions/{submissionId}/events`，沿用登录会话、仅提交所有者连接，严格限制同源（D-039）。消息白名单为 `submissionId/processingStatus/statusVersion`，不含源码、verdict 或判题诊断；页面通过所有者查询接口获取实际结果，保留轮询兜底。

### 8.5 编译与测试执行

- 每次正式提交创建一个全新容器。
- 源码只编译一次。
- 每个测试用例启动独立 JVM 进程并清理临时目录。
- 测试按固定顺序执行，遇到第一个非 AC 立即停止。
- 编译失败直接返回 CE。
- 安全违规、总资源预算耗尽或平台异常立即终止。
- 平台异常不得伪装成用户 RE。

输出比较：

- 规范化 Windows/Linux 换行；
- 忽略行末多余空白和文件末尾空行；
- 其他内容保持严格一致。

隐藏测试不得向普通用户返回输入、预期输出、失败编号、通过数量或逐例资源数据。编译错误和公开样例可以显示安全的详细信息。

### 8.6 沙箱安全

容器必须：

- 非 root；
- 禁止联网；
- 根文件系统只读；
- 使用受限临时目录；
- 删除多余 Linux capabilities；
- 启用 no-new-privileges；
- 限制 CPU、内存、进程数、输出量、单用例时间和整次提交预算；
- 不挂载数据库、Redis、MQ 凭证或整套隐藏测试；
- 任何终态都清理容器与临时文件。

普通 Docker 不被视为可以承载任意互联网恶意代码的绝对安全边界。

### 8.7 可复现性

每次正式提交保存：

- 源码及哈希；
- 语言；
- judge_version；
- 资源限制和比较规则版本；
- 测试数据校验值；
- 实际 Docker 镜像 tag 或 digest。

镜像升级只影响新提交，不自动重判历史记录。

### 9.2 作业

## 13. Redis 与 Elasticsearch

### 13.1 Redis

Redis 用于：

- 公共题目详情和官方题单缓存；
- 登录会话和 Token 失效状态缓存；
- 登录、提交和评论限流；
- 连续点击的短期幂等拦截。

MySQL 始终是用户、题目、作业、提交和判题结果的最终事实来源。

缓存策略：

- Cache-Aside；
- 修改 MySQL 时同事务写缓存失效 Outbox；
- 事务后可靠删除缓存；
- 空值短 TTL、防穿透；
- TTL 随机抖动、防雪崩；
- 热点缓存单请求重建、防击穿。

Redis 故障时：

- 公共缓存回退 MySQL；
- 会话回退 MySQL 权威记录；
- 限流回退单实例保守策略，并结合数据库排队数量；
- 不允许跳过安全检查。

### 13.2 Elasticsearch

- 只索引公共题目的标题、题面纯文本、难度和标签。
- 支持全文检索、难度/标签筛选和关键词高亮。
- 不索引班级私有题、隐藏测试、用户源码、题解和论坛。
- MySQL 是唯一事实来源。
- 发布、修改、下架通过 Outbox 同步。
- 索引消费者使用“题目 ID + 数据版本”幂等更新。
- 失败有限重试，最终进入死信队列。
- 提供从 MySQL 全量重建索引的管理操作。
- ES 仅返回候选 ID 和排序；API 批量查询 MySQL 复核当前公开状态。

ES 故障时，熔断并回退到 MySQL 标题关键词及精确标签/难度筛选；暂时失去正文检索、相关度排序和高亮，并显示降级状态。

## 14. 非功能要求

### 14.1 一致性与可靠性

- 数据库和 RabbitMQ 使用事务 Outbox，不使用分布式事务。
- 所有消费者按至少一次投递设计，必须幂等。
- Redis 和 ES 不得成为权限或业务事实的唯一来源。
- 平台失败与用户代码错误严格区分。

### 14.2 可观测性

- 结构化日志关联 requestId、submissionId 和 judgeTaskId。
- 提供健康检查和就绪检查。
- 采集请求延迟、队列深度、排队时间、判题耗时、结果分布、重试、死信、缓存命中、降级和容器清理失败。
- 使用最小 Prometheus/Grafana 面板。
- 不在 V1.0 建设完整 ELK 和分布式追踪。

### 14.3 测试

- 单元测试覆盖状态机、权限和关键规则。
- 集成测试覆盖 MySQL、Redis、RabbitMQ、ES、Outbox 和幂等。
- 权限矩阵测试覆盖用户、班级角色和后台角色。
- 端到端覆盖注册到 AC、班级作业、出题审核和异常任务重试。
- 沙箱测试覆盖无限循环、内存耗尽、进程爆炸、输出超限、联网、写文件、提权尝试、异常退出和清理。
- 不追求没有意义的 100% 行覆盖率。

### 14.4 部署、配置与备份

- 日常开发可使用 Windows、Docker Desktop 或 WSL2。
- 最终验收和性能数据来自固定 Linux 环境。
- 单机 Docker Compose 部署 Nginx、API、Judge Worker、MySQL、Redis、RabbitMQ、ES 和监控。
- 只有 HTTP/HTTPS 对外；基础设施只在内部网络。
- 真实密钥不得进入仓库、镜像、日志或错误响应。
- Flyway 管理数据库迁移。
- MySQL 每日加密备份并复制到服务器外；至少保留 7 份日备份和 4 份周备份。
- 正式验收前必须完成一次恢复演练和一次应用回滚演练。

### 14.5 性能真实性

- 不预写 QPS。
- Web API、缓存/搜索、提交接收、判题吞吐和 WebSocket 延迟分别测试。
- 所有数据记录固定环境、数据集、预热、并发、时长、错误率、资源占用和 Git commit。
- 只有可复现的优化前后对比才能写“提升百分比”。
