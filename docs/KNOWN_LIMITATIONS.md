# ForgeOJ 已知限制

> 本文记录真实、可解释的范围限制，不记录故意制造的 Bug。  
> M0 已于 2026-09-30 通过固定 Linux/amd64 全量构建、六 verdict 真实进程链路和最终 20 项门禁审计，状态为 `VERIFIED`；M1 为 `IN_PROGRESS`，尚未通过门禁。下列内容是已接受的设计边界，开发中发现的新限制必须继续追加。

## 1. 为什么保留这份文档

“不完美”应该来自工程取舍，而不是来自未修复的明显错误。每项限制都要能回答四个问题：影响什么、为什么接受、现在如何降低风险、未来怎样改进。

## 2. 当前已接受限制

| 编号 | 限制 | 影响 | 接受原因 | 当前规避措施 | 未来方向 |
|---|---|---|---|---|---|
| L-001 | 只支持 Java 21 | 其他语言和旧/新 JDK 代码不能提交 | 先控制镜像、编译和安全变量 | 题目明确环境并固定镜像 digest | 真实需求足够时按语言独立镜像和队列扩展 |
| L-002 | 只支持单文件 `Main.java` | 不支持多文件、Maven/Gradle 和第三方库 | 降低依赖供应链与构建复杂度 | 页面提供清晰模板和编译约束 | 另立多文件项目题方案，不直接放开宿主构建工具 |
| L-003 | 只支持标准输入输出 | 不支持函数题、交互题和 Special Judge | 先验证确定性判题链路 | 题面和样例统一输入输出规范 | 后续可先增加受控函数题包装器 |
| L-004 | 不支持部分分 | 一个测试失败即整题不通过 | 简化结果模型和教学解释 | 题目难度与测试设计避免依赖分组得分 | 后续引入测试组和计分规则版本化 |
| L-005 | 单次提交使用新容器 | 判题吞吐和延迟受容器启动影响 | 强化提交隔离并便于清理 | 排队、并发限制和独立 Worker | 经过安全评估后研究预热池或更强沙箱 |
| L-006 | 普通 Docker 不是绝对安全边界 | 不适合开放给无限匿名恶意用户 | 个人项目无法承诺专业沙箱级隔离 | 实名式注册、邮箱验证、小范围试用、禁网、非 root、资源限制 | 研究 gVisor、Firecracker 或独立判题节点 |
| L-007 | V1 为单机部署 | 主机故障会导致服务中断 | 项目规模和成本不支持高可用集群 | 备份、恢复文档、健康检查和镜像回滚 | 有真实负载后再拆分数据库和 Worker 节点 |
| L-008 | 不承诺 SLA | 用户不能依赖其作为关键教学基础设施 | 小规模作品没有 7x24 运维团队 | 维护提示、提交开关和故障记录 | 根据试运行数据制定服务目标 |
| L-009 | MySQL、Redis、ES、MQ 同机时资源竞争 | 内存压力可能影响判题和搜索 | 单机部署便于学习和控制成本 | 资源配额、监控、保守并发和容量测试 | 将 Judge Worker、ES 或数据库迁出独立节点 |
| L-010 | Redis 降级会降低性能 | 数据库压力增大，部分限流更保守 | Redis 不是事实来源，优先保证正确性 | MySQL 回退、单机限流和提交排队上限 | 多级限流和独立高可用 Redis |
| L-011 | ES 故障时搜索能力下降 | 无正文检索、高亮和相关度排序 | 搜索增强不能阻塞题库可用性 | 回退标题关键字与标签/难度精确筛选 | 建立更完善的索引监控和恢复自动化 |
| L-012 | 异步链路存在短暂最终一致窗口 | 提交后不会立刻出现最终结果 | 可靠异步判题必然涉及排队和重试 | 明确 QUEUED/RUNNING/RETRYING 状态，WS 推送加轮询 | 优化排队与弹性 Worker，不伪装同步完成 |
| L-013 | 隐藏测试第一版保存在 MySQL | 大文件不合适，权限配置错误会扩大影响 | 初期数据规模小，可减少组件数量 | 独立受限表、最小账号权限、审计和大小限制 | 数据规模增长后迁移加密对象存储 |
| L-014 | 每道正式题只要求一份官方题解 | 不能覆盖所有算法思路 | 保证每道题至少有学习出口，控制审核成本 | V1.1 允许用户发布多种 AC 题解 | 由高质量社区内容补充并建立精选机制 |
| L-015 | 班级身份不验证真实教师 | OWNER 不代表学校认证教师 | 产品面向任意学习小组 | UI 使用“创建者/班级负责人”语义并限制班级内权限 | 若进入学校场景再接组织认证 |
| L-016 | 教师只能看本班作业相关提交 | 不能查看成员全部刷题行为 | 保护用户私人练习与源码 | 作业快照和资源级授权 | 只有用户主动授权时增加更广学习分析 |
| L-017 | 个人题单 V1.0 与 V1.1 仅私有 | 用户不能分享自建题单 | 个人学习列表具有隐私属性，公开闭环优先级低 | 官方题单承担公共学习路径 | V2 候选：显式发布、取消公开、收藏/复制、举报和下架 |
| L-018 | 用户题解延后到 V1.1 | V1.0 社区互动较弱 | 防止核心判题与班级功能被社交范围拖慢 | V1.0 提供官方题解 | 完成 V1.0 后按证据和时间实施 V1.1 |
| L-019 | 评论最多三层 | 不适合长链式讨论 | 控制页面、查询和审核复杂度 | 继续讨论时新开根评论 | V2 论坛评估更适合长讨论的数据模型 |
| L-020 | 不做抄袭检测 | 不能自动识别复制代码 | 可靠抄袭检测本身是独立复杂领域 | 班级侧展示真实提交与时间，不作自动定罪 | 有真实教学需求后独立调研相似度和申诉流程 |
| L-021 | 不做竞赛与排行榜 | 不支持竞赛计时、封榜和排名 | 与学习和小班作业主线不同 | 官方题单和个人进度替代 | 需要竞赛时重新设计一致性与反作弊 |

| L-027 | 满队列重试占用原运行槽位 | 对外 `RUNNING` 可能处于退避等待；同用户后续任务暂不能执行 | 用户确认运行时仍允许三个排队，不预留名额，亦不能形成第四个排队任务 | 内部 `WAITING_RETRY` 清除执行 lease，有限 attempt/退避、Outbox 与恢复扫描保证继续；运行 M1 必须启用恢复扫描 | 经公平性测试后另行评估调度设计，见 D-038 |

### L-031：孤儿沙箱清理保守且依赖已提交的 attempt 关闭事实

- 影响：进程被杀死后存在租约到期、恢复领取和清理扫描的窗口；Docker/数据库不可用时清理延后。旧 M0 格式或本数据库无法确认归属的容器不会自动删除。
- 原因：不能以标签或本地时间认定任意沙箱已失去所有权，也不能让新 Worker 启动误删其他活跃 Worker 的容器。
- 当前缓解：每 attempt 独立名称与标签；使用完整不可变容器 ID；正常 finally 核对归属清理，启动与周期扫描只删除已关闭 attempt；默认同时启用 sandbox 与 recovery 才有周期清理。实际崩溃恢复与多 Worker 保留测试见 `M1-FAULT-RECOVERY-VALIDATION.md`。
- 操作边界：部署切换前停止/排空旧 Worker，按完整容器 ID、标签、数据库任务及活跃进程核实 legacy 资源；未经核实不全局清理。固定 Linux 子 JVM 故障复验已通过，见 `M1-FIXED-LINUX-VALIDATION.md`；未来运维闭环仍需要补未知/失败清理告警与处置，当前没有清理延迟或容量 SLA，完整独立链路与最终门禁未关闭。

### L-032：沙箱资源约束不等于完整安全判定

- 当前证据：有界原创程序实际触发 cgroup v2 内存/PID、JVM 堆、tmpfs 限制，验证禁网、只读、非 root、无 capabilities、no-new-privileges 和隐藏数据/凭据隔离；修复逐例文件/子进程残留与 `/dev/shm` 绕过，见 `M1-SANDBOX-SECURITY-VALIDATION.md`。
- 当前补齐：V3 CHECK 已允许八类；随后发现原 verdict 列 16 字符不能保存安全结果，V5 扩为 32。Worker 现在按逐例 cgroup oom/PID max 增量产生 MLE/SECURITY_VIOLATION；两类结果走 FINISHED/SUCCEEDED、终态后 ACK 和重复投递吸收。详见 M1 设计 5.3、D-040 与 `M1-RESOURCE-VERDICT-VALIDATION.md`。
- 仍缺：纯 Java 堆/metaspace OOM 没有内核事件时，无法仅用不可信异常文本确认 MLE；被捕获可按输出继续，未捕获为 RE。联网/写只读/提权拒绝没有逐次可信审计，不一概判安全违规。只有 oom_kill 增量但没有局部 oom 证据按平台故障；证据缺失/非法不猜 verdict。
- 范围：PID 测试是有界创建和独立的非协作子进程超时测试，不是任意递归 fork 风暴/内核逃逸证明。控制命令失败会中止后续用例并删除该容器；daemon 不可用时仍依赖 L-031 最终回收。cgroup 事件测试要求 Linux cgroup v2，不静默跳过不兼容环境。
- 下一步：固定 Linux 自动化/子 Worker 故障/安全/资源复验已通过（158 项后端、8 项前端），完整独立 Linux M1 链路、运维边界和最终门禁仍待完成，同时保留 JVM 内存事件与拒绝操作审计的上述差距。普通 Docker 仅用于受控小规模运行，M5 固定 Linux 主机安全验收不因此关闭。

## 4. 关闭限制的规则

限制只有在代码、迁移、自动化测试和目标 Linux 环境验收均完成后才能标为已解决。关闭时保留原记录，并链接替代设计与 release，不能直接删除历史。
