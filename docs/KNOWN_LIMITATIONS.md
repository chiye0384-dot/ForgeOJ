# ForgeOJ 已知限制

> 本文记录真实、可解释的范围限制，不记录故意制造的 Bug。  
> M0 已通过 20 项门禁；M1 于 2026-10-02 通过 [15 项最终门禁审计](M1-GATE-AUDIT.md)，均为 `VERIFIED`。M2 普通账号单元现为 [VERIFIED](M2-ACCOUNTS-VALIDATION.md)，完整 M2 保持 `IN_PROGRESS`；L-026、L-028 已关闭并保留历史，L-027、L-029～L-035 等有效边界继续保留。M4 运维与 M5 生产主机验收仍未完成。下列内容是已接受的设计边界，开发中发现的新限制必须继续追加。

## 1. 为什么保留这份文档

“不完美”应该来自工程取舍，而不是来自未修复的明显错误。每项限制都要能回答四个问题：影响什么、为什么接受、现在如何降低风险、未来怎样改进。

## 2. 当前已接受限制

| 编号 | 限制 | 影响 | 接受原因 | 当前规避措施 | 未来方向 |
|---|---|---|---|---|---|
| L-001 | 只支持 Java 21 | 其他语言和旧/新 JDK 代码不能提交 | 先控制镜像、编译和安全变量 | 题目明确环境并固定镜像 digest | 真实需求足够时按语言独立镜像和队列扩展 |
| L-002 | 只支持单文件 `Main.java` | 不支持多文件、Maven/Gradle 和第三方库 | 降低依赖供应链与构建复杂度 | 页面提供清晰模板和编译约束 | 另立多文件项目题方案，不直接放开宿主构建工具 |
| L-003 | 只支持标准输入输出 | 不支持函数题、交互题和 Special Judge | 先验证确定性判题链路 | 题面和样例统一输入输出规范 | 后续可先增加受控函数题包装器 |
| L-004 | 不支持部分分 | 一个测试失败即整题不通过 | 简化结果模型和教学解释 | 题目难度与测试设计避免依赖分组得分 | 后续引入测试组和计分规则版本化 |

| L-010 | Redis 降级会降低性能 | 数据库压力增大，部分限流更保守 | Redis 不是事实来源，优先保证正确性 | MySQL 回退、单机限流和提交排队上限 | 多级限流和独立高可用 Redis |

### L-031：孤儿沙箱清理保守且依赖已提交的 attempt 关闭事实

- 影响：进程被杀死后存在租约到期、恢复领取和清理扫描的窗口；Docker/数据库不可用时清理延后。旧 M0 格式或本数据库无法确认归属的容器不会自动删除。
- 原因：不能以标签或本地时间认定任意沙箱已失去所有权，也不能让新 Worker 启动误删其他活跃 Worker 的容器。
- 当前缓解：每 attempt 独立名称与标签；使用完整不可变容器 ID；正常 finally 核对归属清理，启动与周期扫描只删除已关闭 attempt；默认同时启用 sandbox 与 recovery 才有周期清理。实际崩溃恢复与多 Worker 保留测试见 `M1-FAULT-RECOVERY-VALIDATION.md`。
- 操作边界：部署切换前停止/排空旧 Worker，按完整容器 ID、标签、数据库任务及活跃进程核实 legacy 资源；未经核实不全局清理。固定 Linux 子 JVM 故障复验、独立完整链路和最终 M1 审计已通过，见 `M1-GATE-AUDIT.md`。未知/失败清理告警与处置仍属于后续运维治理；本轮不提供清理延迟或容量 SLA，M1 PASS 仅指可确认归属且 DB/daemon 可用条件下的最终回收。

### L-032：沙箱资源约束不等于完整安全判定

- 当前证据：有界原创程序实际触发 cgroup v2 内存/PID、JVM 堆、tmpfs 限制，验证禁网、只读、非 root、无 capabilities、no-new-privileges 和隐藏数据/凭据隔离；修复逐例文件/子进程残留与 `/dev/shm` 绕过，见 `M1-SANDBOX-SECURITY-VALIDATION.md`。
- 当前补齐：V3 CHECK 已允许八类；随后发现原 verdict 列 16 字符不能保存安全结果，V5 扩为 32。Worker 现在按逐例 cgroup oom/PID max 增量产生 MLE/SECURITY_VIOLATION；两类结果走 FINISHED/SUCCEEDED、终态后 ACK 和重复投递吸收。详见 M1 设计 5.3、D-040 与 `M1-RESOURCE-VERDICT-VALIDATION.md`。
- 仍缺：纯 Java 堆/metaspace OOM 没有内核事件时，无法仅用不可信异常文本确认 MLE；被捕获可按输出继续，未捕获为 RE。联网/写只读/提权拒绝没有逐次可信审计，不一概判安全违规。只有 oom_kill 增量但没有局部 oom 证据按平台故障；证据缺失/非法不猜 verdict。
- 范围：PID 测试是有界创建和独立的非协作子进程超时测试，不是任意递归 fork 风暴/内核逃逸证明。控制命令失败会中止后续用例并删除该容器；daemon 不可用时仍依赖 L-031 最终回收。cgroup 事件测试要求 Linux cgroup v2，不静默跳过不兼容环境。
- 验收状态：补齐门禁回归后的固定 Linux 后端 160/前端 8 项、五项子 Worker 故障/凭据、16 项安全程序，以及相同运行时代码的八 verdict/真实浏览器独立链路已通过，M1 最终 15 门禁 PASS，见 `M1-GATE-AUDIT.md`。保留 JVM 内存事件与拒绝操作审计的上述差距；普通 Docker 仅用于受控小规模运行，M4 运维和 M5 固定 Linux 主机安全验收不因此关闭。

### L-033：普通账号真实服务商投递尚未验收

- 首次发现版本：M2 普通账号单元开发阶段（当时 `IN_PROGRESS`，2026-10-02）。账号单元现已验证本地闭环，本条生产投递限制仍有效，见 [账号验收](M2-ACCOUNTS-VALIDATION.md)。
- 影响：默认 `forgeoj.auth.mail.mode=disabled` 不投递激活/重置/补邮箱邮件；本轮不证明真实邮箱可达、SMTP 配置、退信、可靠重试或生产注册可用。发送失败时账号/摘要仍已提交，公开响应不能透露发送状态。
- 选择原因：先使用隔离开发数据验证完整账号规则，避免连接真实邮箱或引入外部凭据和费用；不让业务事务依赖外部邮件服务。
- 当前缓解：`LocalAccountMail` 仅 dev/test、`127.0.0.1` 独立端口、最多 100 条内存消息；进程退出清空，不向普通业务 API、日志或持久文件泄露邮件令牌。`AccountMailDelivery` 为投递扩展接口；disabled/投递异常仅记固定 `account.mail_delivery_failed`，可在冷却后重发未过期流程。
- 未来方案：上线注册/找回前提供生产 `AccountMailDelivery`（如自有 `@Primary` SMTP adapter），确认密钥注入、超时、失败处理和端到端投递；需要可靠邮件时另行设计持久 Outbox/重试。开发模拟器不能以改监听地址的方式公开给远程用户。

2026-10-03 增量：已实现按模式选择的 `SmtpAccountMail`，默认 disabled、显式启用、必需 STARTTLS/implicit TLS、正常信任链/主机校验及有界 socket 超时，Windows 11 项真实 loopback SMTP/TLS 测试通过。该增量没有真实服务商配置或邮箱送达证据，生产投递限制继续有效，不能以本地协议测试关闭本条。现有发信仍在提交后直接调用，无持久邮件 Outbox；见 [SMTP 设计](M2-SMTP-DESIGN.md)、U-010 与后续统一验收记录。上述首次发现/未来方案保留当时事实。

### L-034：账号限流有界但进程部分不跨重启或节点共享

- 影响：登录、refresh、邮件请求及令牌消费的 IP/标识限流存于单个 API 进程；重启清空，多实例不能形成共同计数，尚无代理 IP 信任链或分布式风控证据。
- 选择原因：Redis 缓存、分布式限流与故障降级属于 M4；当前先保守限制单实例，不增加未验证基础设施。
- 当前缓解：进程 limiter 最多 10,000 个键，容量用尽时拒绝新键；默认登录 IP 30/5min、标识 10/5min，邮件 IP 20/hour，消费 IP 30/5min、refresh IP 60/5min。邮件同用户同用途的 60 秒冷却与每小时 5 次限制由 MySQL 记录，在重启后仍有效；对无效身份使用一致提示。
- 未来方案：M4 建立 Redis 共享计数与 MySQL/单实例保守降级，确认部署代理的可信来源；不以浏览器按钮禁用代替服务端限制。测试中的公开限流倍率只减轻 disposable 集成测试互扰，不能用于生产容量或抗攻击声明。

### L-035：JWT 与 refresh 保持可撤销会话的成本和失败边界

- 影响：每个受保护 HTTP 请求查询 MySQL 会话；数据库不可用时 fail closed。JWT 最长 5 分钟、会话绝对期限 7 天，refresh 单次轮换；响应丢失或未协调的并发轮换可能使当前会话被撤销并要求重登录。已消费摘要为重用检测保留，尚无按会话期限清理认证历史的运维任务。
- 选择原因：未过期 JWT 也必须服从退出、改密、重置和停用，MySQL 是会话权威；不能以网络重试为理由反复接受旧 refresh。
- 当前缓解：账号→会话→令牌锁序、事务内敏感写复核，浏览器在同一页合并刷新，支持 Web Locks 时通过跨标签锁及再次 GET session 协调；缺少 Web Locks 时仍可登录，短 JWT 到期后要求重登录，不自动旋转共享 refresh。其他独立会话不因当前 sid 重用而失效。Cookie 仅限同源、HttpOnly、SameSite=Strict，生产 Secure，写操作保留 CSRF/Origin。
- 升级兼容：旧 ACTIVE 账号仍可用户名登录，但空邮箱没有伪造验证时间，需当前密码+验证后补邮箱才能找回；旧进程会话需重新登录。dev 缺省随机签名密钥在重启后变化；生产必须外部配置至少 32 字节的私有随机密钥，不能使用公开测试密钥。
- 未来方案：M4 评估权威会话缓存及故障回退；按绝对到期事实设计摘要清理和密钥轮换。浏览器兼容性、生产 HTTPS/代理配置与目标部署的持久会话恢复需单独验收，不能由开发页测试替代。

## 4. 关闭限制的规则

限制只有在代码、迁移、自动化测试和目标 Linux 环境验收均完成后才能标为已解决。关闭时保留原记录，并链接替代设计与 release，不能直接删除历史。


### L-037：固定 Linux 验证依赖兄弟容器直连的测试网络

- 本机 Docker Desktop 映射端口的 JDBC 路线多次在 fixture 首次连接超时；HTTP 探针或重启不能替代全量 JDBC 证据。仅测试源码 opt-in 使用 inspect 本人的 MySQL bridge IPv4，默认本机仍原路线，固定 Linux 全量 269/45 与实际重放通过。
- 固定验证脚本目前要求 builder/Testcontainers 共享默认 bridge；其他 Docker 网络配置须重新证明路线，禁止猜网关、放宽生产权限或测试自动重试。两个实际生产 JAR 均无测试适配。
- 见 [题解访问验收中的失败诊断](M2-SOLUTION-ACCESS-VALIDATION.md)。不是生产高可用/安全/性能结论。

### L-038：自测保留最少生命周期与关闭 attempt 元数据

- V14 自测代码、输入和输出在终态24小时后隐藏并由有界批次物理清理；queued/running/retrying 不清理。最少的 snapshot ID/hash/resource metadata、job幂等绑定和关闭 attempt 永久保留，保证旧请求不能重复执行及沙箱孤儿清理拥有权威关闭证明。这部分元数据仍会累积，不是自测代码或输出永久保存。
- 后续归档必须同时保留不可重放的幂等事实和可信关闭证明，重新验收 orphan fail-closed，不能只加 TTL 删除。正式 Submission 不受影响。
- 验证范围与外部 SMTP 范围见 [自测验收](M2-SELF-TEST-VALIDATION.md)，不是生产存储或性能结论。
