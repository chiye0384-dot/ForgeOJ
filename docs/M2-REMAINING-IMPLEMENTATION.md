# M2 剩余功能实施与验收顺序

> 2026-10-03，完整 M2 为 `IN_PROGRESS`。用户要求从已验收的普通账号单元继续，列出步骤并开始实现。起点为 `feat/m2-accounts` 的 `36cb6c4`；本文件不覆盖需求、决策或账号验收事实。

## 1. 顺序与交付边界

1. 公共题库：标题关键词、难度、标签、分页及按实际 slug 进入作答。保留原 `/` 入口与题目详情八字段契约。
2. 题目内容：本人题目草稿、逐条/ZIP 测试数据、私有参考程序的正式沙箱验证、官方题解代码验证、不可变送审版本与归档。独立管理员认证和完整审核后台仍在 M4；不能用普通用户权限替代 CONTENT_REVIEWER，也不能把开发 fixture 称为已审核正式内容。
3. 学习记录：官方题单、个人私有题单、当前判题版本本人真实 AC 进度、服务端代码草稿和乐观版本冲突、本人正式提交历史。
4. 自测与题解：自定义输入的独立运行任务、快照和短期记录；保持正式提交永久且不可变；AC 解锁与主动提前查看记录，不能以自测成功生成 AC。
5. SMTP：配置型适配与本地 TLS 协议验证可先并行；真实服务商配置、允许的收件地址与真实投递结果须单独核实。密码只通过本机环境变量提供，不进入源码、日志或证据。
6. 完整验收：固定 Linux 全部检查、实际浏览器注册到 AC、版本与历史保留、隐藏测试/参考程序权限、题单隔离、停用后的会话撤销、队列和日志审计及精确清理；满足全部 M2 门禁后才提升里程碑状态。

## 2. 第一个题库单元

### 接口与数据

- `GET /api/v1/problems`：`keyword`（标题字面子串，最长 100）、`difficulty`（EASY/MEDIUM/HARD）、`tag`（最长 32）、`page`（默认 1）、`size`（默认 20，最大 50）。固定 problem ID 升序；分页偏移使用有界 long。
- 响应仅为 `{items,page,size,total}`，条目仅含 `{slug,title,difficulty,tags,judgeVersion}`。标签接口为 `GET /api/v1/problem-tags`，响应 `{tags}`；避免与现有合法 slug 路由冲突。
- 所有列表、计数和标签只来自 ACTIVE 且具有当前判题版本的题目。标签筛选使用 EXISTS，当前页标签批量查询，避免重复行和逐题查询。计数、页面和标签使用只读可重复读事务。
- 新增 V7：可空 difficulty 和 problem_tag；旧题难度保持未标注，不改 V1～V6，不重写判题版本或历史记录。API 对标签仅有 SELECT，Worker 无新增标签权限。
- 标题 `%`、`_` 和转义符作为普通文字查询，全部参数绑定。原详情仍为八字段，不读取隐藏数据、参考程序、他人源码或个人学习记录。

### D-032 分页评估

首个查询是固定排序、单一主体表和 EXISTS 标签条件；COUNT 是同条件单独查询，LIMIT/OFFSET 显式且有界。当前用 MyBatis 原生 SQL 即可完整表达语义，避免引入分页拦截器及额外 Boot 4 兼容/依赖许可维护成本。PageHelper 本轮保持 DEFERRED；后续复杂历史列表出现明确收益时再过版本和许可证门禁。此选择不宣称深分页具有固定成本，也不宣称已做性能验收。

### 前端与验证

- `/problems` 可匿名浏览；URL 保留筛选和页码；应用筛选回到第一页，过期异步响应不能覆盖新页面。
- `/problems/:slug` 使用实际题目；切题卸载旧监控，保留 `/` 的原 A+B 示例。其他题使用中性 Java Main 模板。
- 登录、退出、切题和提交异步响应需验证操作代次，防止退出后的迟到响应恢复身份或通知。
- 验证覆盖真实 MySQL 迁移/权限/筛选/分页/字段白名单，前端路由/响应乱序/切题/退出，固定 Linux 和从第二道原创测试题进入提交到真实 AC 的浏览器链路。
