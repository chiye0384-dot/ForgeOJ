# M2 independent custom-input self-test

Status: VERIFIED (2026-10-05). Implements Requirements 8.2 and the existing M1 execution boundaries. Evidence: [validation](M2-SELF-TEST-VALIDATION.md). Full M2 remains IN_PROGRESS pending final milestone audit.

Clicking Run freezes Java 21 source and a single custom input. The job uses a separate durable queue and immutable snapshot; it never creates a Submission, loads official tests, awards AC, changes learning progress or unlocks solutions. Successful execution is named SUCCESS; compilation/runtime/resource failures are execution outcomes. Platform failures use the same bounded lease recovery and commit-before-ACK rules as formal judging.

Formal judging, author validation/output previews and self-tests share the authoritative per-user quota: one running reservation (including WAITING_RETRY) and three queued jobs. Each consumer has its own bounded listener, so one queue cannot occupy the other's listener. Queued self-tests can be cancelled; running jobs cannot be interrupted by users. Worker completion requires the active attempt and unexpired token. Closed self-test attempts extend the authoritative sandbox orphan lookup.

POST /api/v1/problems/{slug}/self-tests accepts exactly requestId, language, sourceCode and input. Owner/request replay must match the frozen slug/language/source/input; conflicting reuse returns 409. GET /api/v1/self-tests/{id}, GET /api/v1/me/self-tests?problemSlug=... and POST /api/v1/self-tests/{id}/cancel are owner-only and no-store. Missing, foreign, malformed and expired IDs return 404. Input may be empty; source <=64 KiB, custom input <=1 MiB, no NUL. Output is bounded by both the public version's original output limit and 1 MiB, strict UTF-8 and digest checked. No user diagnostic/code/input/output is written to lifecycle logs or MQ.

Terminal private source/input/output are retained for 24 hours, then excluded from reads and physically purged in bounded batches. Running/queued/retrying payloads cannot be purged. Minimal immutable IDs, hashes, resource metadata, job lifecycle and attempt tombstones remain, preserving idempotency conflicts, audit and permanent closed-attempt proof for orphan cleanup. Expired request replay returns 410; it cannot create a second execution. Formal submission retention is unchanged. Automatic maintenance can be disabled for tests; no API Docker access or deletion of formal records is introduced.

Frontend keeps captured request/payload for retries after an ambiguous network failure, and allows an explicit new run. Polling is bounded and can be resumed manually. Identity changes/unmount invalidate late responses and stop polling. Local code/input edits after clicking Run never alter the frozen request or displayed snapshot.

V14 adds isolated tables and grants: API can insert immutable snapshot/payload/job and only update cancellation fields; Worker cannot read mutable authoring/account/learning state or insert/edit a snapshot. API may delete only expired terminal payload/output through its maintenance transaction. Neither role deletes lifecycle/attempt tombstones. MQ has exactly taskId, snapshotId, taskType=SELF_TEST, contractVersion=1. Existing self-test queue arguments remain unchanged; platform exhaustion emits a separate ID-only self-test dead event. Malformed messages are rejected without requeue.

Acceptance requires fresh migration/owner/idempotency/quota/cancellation/TTL tests, real sandbox generation and recovery tests, frontend lifecycle tests, fixed Linux verification and actual browser execution using the exact verified artifacts. External SMTP and M4 publication are separate outstanding work.
