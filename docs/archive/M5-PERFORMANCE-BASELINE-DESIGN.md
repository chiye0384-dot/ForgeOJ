# M5 本机隔离性能基线设计

2026-10-28，沿用户“继续”授权执行首个有限性能单元；遵循 [总性能计划](Performance-Test-Plan.md)。这不是完整容量、优化对比或长稳验收。使用当前 428 项冻结输入对应的原 Linux 构件，不改业务代码、数据库授权或限流规则，不购买或操作线上实例。

## 本轮固定范围

- Windows 开发机上的 Docker Desktop Linux/amd64 引擎，真实 Nginx HTTPS、API、MySQL、Redis、Worker 和现有监控；负载客户端使用已批准的固定 Node 24.14.1 镜像，在独立项目的 edge 桥接网络访问 Web。不是手机 Wi-Fi、公网 RTT 或独立云主机。
- 一份新建空库项目，显式测试 fixture：原两数之和和一个普通测试账号；300 道原创合成公共题，短/中/长题面各 100，道道具有真实 judge version、三个原公开 fixture 用例、难度和标签。没有真实用户、默认生产账号或真实邮件。用户数/历史量/班级/作业等大数据集不在这次范围。
- 仅修改这份 ignored 包的容器 CPU 限额：API/Worker/MySQL/ES 各 2 CPU、Rabbit/Redis/Web 各 1、Prometheus/Grafana 各 0.5；沿用原内存/PID 限制。负载客户端 1 CPU、512 MiB、128 PID、非 root、只读根目录、无 Docker socket，不修改宿主/Docker 设置。
- Web：一轮 300 个不同题目详情首次读取；随后标题/难度/标签筛选列表，以及全部题目轮转的详情读取，分别并发 1/4/8、每级 20 秒、两轮重复。每个详情阶段先逐题预热；首次读取只是 Redis 键未命中，不是冷 JVM/冷磁盘。保留首轮原始数据，不选最快结果。
- 判题：顺序 6 次 AC，加 WA/CE/RE/TLE/OLE 各一次；同一原公开测试题，新的编译/运行容器，保持单个在途请求。一次相同幂等键回放单独记录，不计作新任务。记录接收延迟、客户端轮询可见时间、数据库排队/处理时间、真实 verdict、唯一 submission/task/attempt/outbox 和清理。不是判题饱和吞吐，MLE、长/中/短隐藏输入性能及通知延迟留后续。

## 测量和验收

客户端采用闭环固定并发：前一个请求完成后才发下一个请求。记录这个模型的到达率受响应时间影响，不将其解读为开放模型的固定到达率或最大容量；方法参照 [k6 开闭环说明](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/)，本轮不引入 k6。

保存每个请求的相对开始时间、持续时间、状态码、超时/网络错误与响应校验结果；不保存 cookie、token、密码、响应源码或隐藏测试。延迟在 HTTPS 响应体读取结束计时，JSON 内容校验另做；5 秒超时，无自动重试。P50/P95/P99 用 nearest-rank，独立从原始 NDJSON 重算，与 Node 摘要比对。状态非 200、超时、网络失败和内容错误分别报告，不能排除后再算漂亮结果。

每阶段约 5 秒一次 Docker stats，保留 CPU%、内存、PID 和时间戳，并记录实际资源限额。Docker Linux CLI 的内存数据扣除了部分缓存，不能称为进程 RSS，依据 [官方 stats 文档](https://docs.docker.com/reference/cli/docker/container/stats/)。客户端同时记录进程 CPU 和 event-loop 延迟，避免忽略负载端瓶颈。API/Worker 固定指标和 MySQL 全局计数前后快照一起保留；不把连接计数当作查询延迟或完整连接池指标。

验收重点是工具/数据集可重复、请求结果正确、原始结果可重算、同一构件/资源条件、所有已接受判题有对应真实终态、无重复业务副作用和拥有者沙箱残留。不给延迟/QPS 预设“好看”门槛；若出现饱和/错误如实保留并定位，不在本轮顺手优化业务。

完整 M5、E-07 性能优化、长稳、故障负载、独立 Linux/云主机容量和 Release/RESUME_READY 均不因本轮局部基线自动完成。

实际执行补充：为避免旧 TTL 在测量期间到期，每个详情阶段只 UNLINK 本实例 300 个已知合成题缓存键，再逐题预热；身份、限流、会话和预算键均不清理。首次工具将 30,000 次请求视为安全上限，实际在 20 秒前触发，被验收器正确拒绝；保留首轮数据后将安全上限提高到 100,000，在同一数据/资源上创建新证据代际完整重跑。客户端源码在每个套件开始冻结复制，不跟随源文件后续变动。
